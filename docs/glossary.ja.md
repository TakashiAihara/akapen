# 用語集

akapen が自分の部品を呼ぶときの言葉と、そのうち二つの意味を持ってしまっている語。

各項目には実体の在り処（型・CSS セレクタ・エンドポイント・パス）を書いてある。定義を信じるのでは
なく確かめられるようにするため。`docs/glossary.md` が正で、この文書はその訳。

## 衝突している語

すでに二つのものを指している語。それぞれ呼び分けの規則を決めてある。修飾した形を使う。裸の語が
混乱の元になっているもの。

| 語 | 一方 | もう一方 | 規則 |
|---|---|---|---|
| anchor | `Comment.anchor` — コメントが書かれた時点のスナップショットの本文。ファイルが先に進んだ後で場所を見つけ直すのに使う | 吹き出しが高さを揃える相手の行。DOM 上でその行に印が付くわけではなく、`layoutRail` が吹き出しの `data-line` を row の `data-start` / `data-end` に突き合わせ、当たった row から位置を決める | 「アンカーテキスト」と「アンカー行」と言う。裸の「アンカー」は使わない |
| 行 (line) | スナップショット内の 1 始まりの行番号（`startLine` / `endLine`） | 読み手が 1 行として見ているもの | line は必ずスナップショットへの番号。画面にあるものは row。折り返した段落は複数行に見えて 1 row |
| block / row | `Block` — 文書の解析単位。`startLine` / `endLine` / `kind` を持つ | `.row` — 1 つの block を描画する要素 | block はモデル、row は要素。block 1 つが row 1 つ |
| コメント | レビューの指摘（`Comment`、`.bubble`） | markdown 内の HTML コメント（`<!-- … -->`）。akapen はこれを本文として表示する | 裸の「コメント」はレビューの指摘。もう一方は「文書内の HTML コメント」と言う |
| mark / marker | 行マーク — コメントが付いた行の左に出る細いアクセント線（`.row.has-comment`） | 件数マーカー — その行のコメント数を示すバッジ。レールを畳んだ時だけガターに出る（`.marker`） | 常に修飾する。「行マーク」「件数マーカー」「リストマーカー」（`.li-marker`、箇条書きの中黒や番号） |
| gutter / rail | ガター — 本文の左側、行番号・件数マーカー・`+` を持つ領域（`.gutter`） | レール — 文書の右側、吹き出しが並ぶ列（`.rail`） | 左がガター、右がレール。「サイドバー」「帯」「ストリップ」とは呼ばない |
| ラウンド | ファイルの凍結スナップショット（`rounds/NNN/`） | `R001` を出しているバッジ（`#round`）とその隣の選択肢（`#roundPick`） | 「ラウンド」はスナップショット。画面側は「ラウンドバッジ」「ラウンドセレクタ」 |
| ドラフト | 書きかけでまだ送っていないコメント（`.bubble.draft`、`startDraft`） | レビュー準備前の GitHub プルリクエスト | プロダクトの中ではドラフト = 未送信のコメント。もう一方はリポジトリの進め方の語であって akapen の語ではない |
| 文書 / ファイル / スナップショット | 実ファイル — いまディスクにあるもの | スナップショット — そのラウンドの凍結コピー（`rounds/NNN/content.md`） | 画面にあるのは常にスナップショットで、実ファイルではない。`Doc` はスナップショットを解析した形（`/api/doc`）。`#doc` はそれを描画する要素 |
| doc / 文書 | `Doc` — ブラウザに渡す解析済みスナップショット（`/api/doc`） | 文書 — 画面に描画されたスナップショット（`#doc`）、および広く「レビュー対象の markdown」 | `Doc` はペイロード、文書は読むもの。文中で「文書」を `doc` と縮めない |
| レビュー | `Review` — `review.json` の中身。ラウンドのメタデータと現在のラウンド番号 | 読んで指摘するという行為 | データを指すときは `review.json` または「レビューストア」（`~/.akapen/reviews/`）と言う |
| インラインレビュー | 文書の場所に紐づいた指摘。akapen の目的そのもの | markdown ファイルの中に直接書き込まれたコメント。akapen は決してしない | 「インライン」なのは読む体験に対してであって、ファイルに対してではない。ファイルは触らない |

## 画面

| 語 | 何か | 実体 |
|---|---|---|
| ステージ | 文書とレールを横に並べるグリッド | `.stage` |
| 文書 | 描画されたスナップショット | `#doc`、`.doc` |
| row | block 1 つを描画したもの | `.row` |
| body | row の中の描画済み markdown | `.body` |
| ガター | 本文の左、ページ余白から本文の手前までの領域。マウスを乗せると `+` が出て、クリックするとその行のコメントが開き、下へドラッグすると行範囲を選べる | `.gutter` |
| `+` ボタン | その行のコメントを開くボタン | `.add` |
| 行番号 | その row の `startLine`。行番号表示が on のときだけ出る | `.lineno`、`body.show-lines`、`lines.toggle` キー |
| 件数マーカー | コメント数のバッジ。レールを畳んだ時だけガターに出る | `.marker`、`body.rail-overlay` |
| 行マーク | コメントが付いた行を示す細いアクセント線 | `.row.has-comment` |
| レール | 文書の右にある吹き出しの列 | `.rail`、`#rail` |
| アンカー済みレール | 画面に出ているラウンドの吹き出し。それぞれアンカー行に高さを揃える | `#railAnchored` |
| 繰り越しレール | 過去ラウンドの未解決コメント。レールの末尾に積む | `#railCarried` |
| 吹き出し | 画面上の 1 コメントと、その返信 | `.bubble` |
| ドラフト吹き出し | 書きかけのコメント | `.bubble.draft` |
| 返信 | コメントに付くメッセージ。1 段だけで、返信に返信はできない | `Reply`、`.reply` |
| トップバー | 画面上端のバー。名前・ファイルパス・ラウンドバッジ・件数・操作 | `.topbar` |
| バナー | スナップショット以降に実ファイルが変わったことを告げる行 | `#banner`、`ChangedState` |
| 履歴バー | 過去ラウンドを見ていることを告げる行。文書に対しては読み取り専用 | `#historyBar` |
| ラウンドバッジ / ラウンドセレクタ | 画面に出ているラウンド。現在のラウンド、または履歴を見ている間は過去のもの。セレクタは現在のラウンドに印を付ける | `#round`、`#roundPick` |
| 件数 | 未解決が何件 / 全何件、加えて繰り越しが何件 | `#count` |

row の状態。重なって付く。

| 語 | 意味 | 実体 |
|---|---|---|
| focused | j/k が乗っている row | `.row.focused` |
| in-range | 選択中の範囲に入っている | `.row.in-range` |
| linked | いま読んでいる吹き出しと結び付いている | `.row.linked` |
| has-comment | このラウンドでコメントが 1 件以上付いている | `.row.has-comment` |

`.row.selected` はスタイルだけあって誰も付けない。状態ではなく残骸。

## 文書のモデル

| 語 | 何か | 実体 |
|---|---|---|
| doc | 解析済みのスナップショット。パス・block の列・行数 | `Doc`、`/api/doc` |
| block | 文書の解析単位。`startLine`..`endLine` にまたがる | `Block` |
| block の種類 | その block が何か。`frontmatter` / `heading` / `paragraph` / `list-item` / `table-row` / `code` / `mermaid` / `hr` | `BlockKind` |
| 行番号 | 1 始まり・両端を含む、スナップショットへの番号。0 行目は存在しない | `LineNumber` |
| 範囲 | コメントが覆う行番号の組。1 row は、その block の両端を持つ範囲 | `Comment` の `startLine` / `endLine` |
| アンカーテキスト | コメントが書かれた時点のスナップショットの本文。ラウンドを越えて場所を運ぶのは行番号ではなくこれ | `Comment.anchor` |
| 行マッピング | markdown のソースを block に割って、描画されたものを行で指せるようにすること | `packages/core/src/blocks.ts` |

## ラウンドと保存

| 語 | 何か | 実体 |
|---|---|---|
| ラウンド | ファイル内容の凍結スナップショット。コメントはこの中の行に紐づく | `rounds/NNN/content.md` |
| 現在のラウンド | 書き込み先のラウンド。新しいコメントを受け付けるのはここだけ。返信と解決はどのラウンドのコメントに対しても行える | `Review.currentRound`、`RoundState.n` |
| ラウンドを見る | 過去ラウンドのスナップショットとコメントを読む。文書に対しては読み取り専用だが、コメントの状態は変えられる | `RoundState.viewing`、`#historyBar` |
| ラウンドを切る | 実ファイルを次のラウンドとして凍結する。人だけが行い、エージェントの保存では起きない | 「End this round」、`#nextRound`、`openRound` |
| 繰り越し | 過去ラウンドの未解決コメント。新しいラウンドには何も引き継がれないので、「画面から消えた」が「対応済み」と読まれないよう別枠で見せる | `carriedOver`、`#railCarried` |
| レビューストア | コメントの置き場所。markdown ファイルの外 | `~/.akapen/reviews/<basename>-<hash>/`、`AKAPEN_HOME` |
| dirty | 実ファイルが現在のラウンドのスナップショットと一致しなくなった状態 | `ChangedState.dirty` |

```text
~/.akapen/reviews/<basename>-<hash>/   # ~/.akapen は既定値。AKAPEN_HOME を設定するとそのルートが変わる
  review.json          # ラウンドのメタデータと現在のラウンド番号
  rounds/
    001/content.md     # 凍結された文書
    001/comments.json  # 001 の行に紐づいたコメント
```

## 人とエージェント

| 語 | 何か | 実体 |
|---|---|---|
| author | 名前であって、それ以上のものではない。何とでも書ける | `Comment.author`、`--author` |
| author kind | 返信を人が書いたのかエージェントが書いたのか。`Reply` にだけあり、コメントにはこのフィールドが無い。サーバが刻印してクライアントの自称は無視するが、現状はすべて `human` を刻印する。自称を認証する手段が無く、エージェントが書き返す経路もまだ無いため | `AuthorKind`（`human` \| `agent`）、`Reply.authorKind` |
| エージェント | 指摘を渡す先のプログラム。コメントを JSON で読み、アンカーテキストで現在のファイルに突き合わせる | `akapen comments <file.md>` |
| resolved | 対応が済んだコメント。状態は過去ラウンドのコメントにも適用される。そうでないと指摘を閉じる手段が無くなる | `Comment.resolved`、`--all` |

## モード

| 語 | 何か |
|---|---|
| review モード | 現在の形。ラウンド・レール・履歴。文書をラウンド単位で読んで指摘する（マイルストーン v0.1） |
| passive モード | ラウンドを持たず、実ファイルに追従して読む形（マイルストーン v0.2） |

## 使わない言い方

| これではなく | こう言う |
|---|---|
| 帯 / ストリップ | ガター |
| サイドバー | レール |
| 画面上のものを指しての「行」 | row |
| 保存の話としての「インラインコメント」 | row に付いたコメント。ファイルには何も書かれない |
